# 1. Scope and design boundary

The conversion does not replace the complete ST-SA3ES front-panel controller. IC701 remains responsible for the original tuning wheel, buttons, presets, frequency display, menu behaviour and VFD refresh. The ESP32 observes the command bus that originally controlled the tuner circuitry and interprets the requested FM channel.

<colgroup>

<p>Do not decode the tuning wheel directly for normal operation. Decode the frequency command generated by IC701. This retains Sony’s native acceleration, direct-entry, preset and menu behaviour without reproducing them in ESP32 firmware.</p></th>

# 3. Verified serial transaction

A clean tuning capture contains a 24-clock transfer while CE is high. DATA remains stable at the sampling edges. The changing transfer is followed by two identical fixed transfers in the examined sequence.

For implementation, treat CE as the frame boundary and collect exactly 24 DATA bits. Reject incomplete frames. Do not infer a frequency from the two fixed follow-up words until their purpose is confirmed.

# 4. Bit and byte order

The analyser records the bits in time order. Each byte is transmitted least-significant bit first. Reversing the bit order within each group of eight converts the wire-level stream into normal byte values.

| **Displayed FM** | **Wire-level 24 bits**     | **Decoded bytes** |
|:----------------:|----------------------------|-------------------|
|    92.55 MHz     | 10001000 00010000 01010100 | 11 08 2A          |
|    92.60 MHz     | 01001000 00010000 01010100 | 12 08 2A          |
|    92.65 MHz     | 11001000 00010000 01010100 | 13 08 2A          |
|    92.70 MHz     | 00101000 00010000 01010100 | 14 08 2A          |

<p>Byte 0 and byte 1 form a little-endian 16-bit PLL divider. Byte 2 was constant at 0x2A in the verified FM steps and is treated as a control/configuration byte, not part of the divider.</p></th>

# 5. FM divider relationship

The decoded divider is consistent with the ST-SA3ES FM intermediate frequency of 10.7 MHz and a 50 kHz reference step. The service manual specifies the FM intermediate frequency as 10.7 MHz. The 50 kHz step is confirmed by the observed one-count increment for each displayed 0.05 MHz tuning step.

<br />

## 5.2 Expected divider range

| **Displayed frequency** | **Divider calculation** | **Expected N** | **Bytes 0–1** |
|:--:|----|----|----|
| 87.50 MHz | (87.50 + 10.70) / 0.05 | 1964 = 0x07AC | AC 07 |
| 92.55 MHz | (92.55 + 10.70) / 0.05 | 2065 = 0x0811 | 11 08 |
| 100.00 MHz | (100.00 + 10.70) / 0.05 | 2214 = 0x08A6 | A6 08 |
| 108.00 MHz | (108.00 + 10.70) / 0.05 | 2374 = 0x0946 | 46 09 |

The frequencies outside the directly captured 92.55–92.70 MHz sequence are calculated expectations. They must be validated against controlled captures before being promoted from expected to verified behaviour.

# 6. ESP32 receive implementation

The first implementation should be a passive sniffer. It must not drive CE, CLK, DATA or D-IN. Passively decode IC701’s requested frequency, log all raw frames and use the resulting kHz value to select a mapped Internet-radio station.

## 6.2 LSB-first frame decoder

<table>
<colgroup>
<col style="width: 100%" />
</colgroup>
<thead>
<tr>
<th>static uint8_t reverse8(uint8_t v) {<br />
v = (v &gt;&gt; 4) | (v &lt;&lt; 4);<br />
v = ((v &amp; 0xCC) &gt;&gt; 2) | ((v &amp; 0x33) &lt;&lt; 2);<br />
v = ((v &amp; 0xAA) &gt;&gt; 1) | ((v &amp; 0x55) &lt;&lt; 1);<br />
return v;<br />
}<br />
<br />
bool decodeSonyFmFrame(uint32_t wireBits, SonyTunerFrame &amp;f) {<br />
// wireBits contains the first received bit at bit 23.<br />
uint8_t wire0 = (wireBits &gt;&gt; 16) &amp; 0xFF;<br />
uint8_t wire1 = (wireBits &gt;&gt; 8) &amp; 0xFF;<br />
uint8_t wire2 = wireBits &amp; 0xFF;<br />
<br />
f.raw[0] = reverse8(wire0);<br />
f.raw[1] = reverse8(wire1);<br />
f.raw[2] = reverse8(wire2);<br />
<br />
f.divider = (uint16_t)f.raw[0] | ((uint16_t)f.raw[1] &lt;&lt; 8);<br />
f.control = f.raw[2];<br />

// until all Sony modes and configuration bits are mapped.<br />
f.valid = (f.rfKHz &gt;= 87500 &amp;&amp; f.rfKHz &lt;= 108000 &amp;&amp;<br />
(f.rfKHz % 50) == 0);<br />
return f.valid;<br />
}</th>

# 7. Station mapping behaviour

The displayed MHz value remains the Sony user-interface state. The ESP32 maps that value to a configured Internet-radio station. The mapping must use integer kHz values to avoid floating-point equality problems.

## 7.1 Duplicate suppression

The capture showed a changing frequency word followed by two identical fixed words. Firmware should not treat all frames as station changes. A conservative first rule is: only accept frames that compute to a valid FM frequency; trigger playback only when the derived kHz value differs from the last accepted value.

# 8. Validation and test plan

| **Test** | **Method** | **Pass condition** |
|:--:|----|----|
| Single-step decoding | Capture four consecutive 0.05 MHz steps | Divider increments by exactly 1 per step |
| Known endpoints | Capture selected values near 87.50 and 108.00 MHz | Decoded integer formula matches the display |
| Preset recall | Recall stored FM presets | Same displayed frequency produces the same decoded divider |
| Fast tuning | Rotate the wheel quickly | No malformed frame is accepted; final selected frequency is correct |
| Direct entry | Enter a frequency using the numeric keys | IC701 command decodes to the displayed channel |
| Power-up | Power on at a known stored station | Initial valid frequency is detected without false station changes |
| Electrical level | Measure all four CN701 lines | Interface design is confirmed safe for the selected ESP32 pins |
